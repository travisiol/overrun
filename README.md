# OVERRUN

A multiplayer-styled voxel zombie survival game with a Solana wallet front end.
Four routes: an animated landing page, a leaderboard, an API-key storefront, and
the game itself behind a wallet gate.

```bash
npm install
npm run dev
```

The brand name lives in exactly one place — [`src/lib/site-config.ts`](src/lib/site-config.ts).
Change `name`, `ticker`, `url` and the X handle there and the whole site follows.

## Routes

| Route             | What it is                                                                |
| ----------------- | ------------------------------------------------------------------------- |
| `/`               | Layered sunset scene: panning clouds, moon, grass, an arm holding the sign |
| `/leaderboard`    | Top survivors by kills or coins, read from `/api/leaderboard`              |
| `/api-keys`       | Three pricing tiers, wallet-gated checkout                                 |
| `/play`           | Wallet gate; once connected, the game takes over the viewport              |
| `/api/leaderboard`| `GET` the board, `POST` a finished run                                     |

## The game

First-person, pointer-locked, rendered with three.js.

- **World** — 96×40×96 voxels generated from value noise, meshed per 16×16 chunk
  so a placed or broken block only rebuilds its own chunk. Trees and broken
  concrete walls scatter over the terrain; the middle is flattened into an arena
  so the spawn is always clear.
- **Combat** — four weapons (sidearm, SMG, shotgun, rifle) with real fire rates,
  magazines, spread cones and range. Shots are hitscan against upright cylinders,
  occluded by the voxel raycast, and the upper body counts as a headshot at 2.1×.
- **Zombies** — walkers, runners and brutes on instanced meshes (six draw calls
  for the whole horde). They steer at the player, climb one-block ledges, and
  **chew through blocks that get in the way**, which is what stops walling
  yourself in from being a win button.
- **Building** — right click or `E` places a barricade for 25 coins, `Q` breaks a
  block. You cannot place one inside your own hitbox.
- **Economy** — 100 coins per kill, spent in the armoury (`B`) on weapons and on
  four upgrade tracks. Waves scale in size and zombie health.

Controls: `WASD` move, `Shift` sprint, `Space` jump, mouse aim, left click shoot,
`R` reload, `1`-`4` weapons, `E`/right click build, `Q` break, `B` armoury.

### Simulation smoke test

The simulation is renderer-free, so it can be driven headlessly:

```bash
npx --yes tsx scripts/smoke-test.mts
```

43 checks covering terrain generation, the voxel raycast, player collision and
step-up, zombie pathing and attacks, the hit-detection cylinder, the coin payout,
and blocks being placed and broken. All 43 pass.

## What is real and what is not

Worth being explicit about, because several things look wired up and are not:

- **Multiplayer is not implemented.** The game is single-player against waves.
  The leaderboard is the only thing shared between players. Real co-op needs a
  websocket server, which this repo does not have.
- **API-key checkout sends no transaction.** Pressing *Buy* shows a notice and
  stops. There is no treasury address and no key-issuing service, so wiring the
  transfer would move real SOL for nothing in return.
- **Progress is browser-local.** Coins, kills, owned weapons and upgrades are
  saved in `localStorage` keyed by wallet address. Nothing is signed and nothing
  is on-chain, so a different machine starts fresh.
- **The leaderboard trusts the client.** Scores post from the browser and are
  only sanity-checked for range. Anyone can curl a fake run. Server-authoritative
  scoring is the fix.
- **Storage is a JSON file** at `.data/leaderboard.json`, which is fine for one
  machine and wrong for anything deployed. Swap
  [`src/lib/leaderboard-store.ts`](src/lib/leaderboard-store.ts) for a database.
- **The RPC defaults to the public mainnet endpoint**, which is rate limited.
  Set `NEXT_PUBLIC_SOLANA_RPC` — see `.env.example`.

## Artwork

Every asset in `public/` is original SVG drawn for this project — the clouds,
grass tiles, moon, dirt mound, and the arm holding the sign — as is the film
grain, which is generated by an SVG filter rather than shipped as a bitmap.
